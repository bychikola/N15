# Дизайн: Личный кабинет под будущую CRM (N15)

Дата: 2026-08-14 · Статус: утверждён пользователем (брейншторм завершён, все 4 секции одобрены)

## Контекст

N15 — Next.js 16 + Payload CMS, сайт недвижимости. Уже есть: регистрация/вход, роли Users (user/agent/admin), коллекция Applications (заявки со статусами и назначенным агентом), Users.favorites (hasMany objects), dashboard ЛК с 4 разделами — но заявки/избранное/профиль захардкожены, сообщения — пустышка, избранное на сайте живёт в localStorage.

Цель: живой ЛК как фундамент CRM — чат с агентом по заявкам, живые заявки/избранное/профиль, видимость непрочитанного.

**Решения пользователя (брейншторм):**
- Объём: всё сразу (данные + чат)
- Модель чата: чат по заявкам (каждая заявка = диалог)
- Сторона агента: агент тоже работает в ЛК (роль agent, видит назначенные диалоги)
- Доставка: polling + REST (обновление каждые 8 сек, без SSE/WebSocket)

## 1. Модель данных и доступ (Payload)

### Applications — привязка к пользователю
- Новое поле `user` (relationship → users, optional): заполняется из сессии при отправке формы авторизованным пользователем
- Access:
  - `read`: user — только свои (`user equals me`); agent — заявки, где он назначен; admin — всё; аноним — ничего
  - `create`: любой (форма на сайте)
  - `update`: agent/admin (статус и назначение); user — нет
  - `delete`: admin

### Messages — новая коллекция (ядро чата)
```
messages:
  application  relationship → applications (required)
  sender       relationship → users (required)
  text         textarea (required)
  read         checkbox (default: false)
```
Access:
- `read`: участники (владелец заявки, назначенный агент, admin)
- `create`: участники
- `update`: участники (только отметка прочтения)
- `delete`: admin

### Agents — связь с учёткой
- Новое поле `user` (relationship → users, optional): один агент каталога = одна учётка role=agent. Через неё — доступ к чатам назначенных заявок

### Избранное — серверное
- `Users.favorites` (уже есть). Кнопка-сердце: залогинен → sync на сервер; гость → localStorage. При входе — одноразовое слияние localStorage → сервер

### Форма «Записаться на просмотр» (страница объекта)
- Становится рабочей: POST в Applications (type=viewing, user из сессии если есть). После отправки — «Заявка принята! Следите за ответом агента в личном кабинете» + ссылка в ЛК

## 2. Чат

### `/lk/messages` — список диалогов
- Строка: фото объекта, название, имя агента (у агента — имя клиента), превью последнего сообщения, время, бейдж непрочитанных
- Сортировка: свежие сверху; непрочитанные выделены золотым бейджем
- У role=agent — только назначенные ему заявки
- Пустое состояние: «Пока нет диалогов…» + CTA «Смотреть каталог»

### `/lk/messages/[applicationId]` — диалог
- Шапка: объект (ссылка) + агент с фото и кнопкой «Позвонить» (tel:)
- Первое сообщение — карточка заявки («Заявка: просмотр, объект»)
- Пузыри: своё — справа (золотая рамка), собеседника — слева (charcoal), время; ✓✓ при прочтении входящего
- Дата-разделители («Сегодня», «Вчера», дата)
- Инпут sticky снизу; Enter — отправить, Shift+Enter — перенос
- Polling 8 сек, только когда вкладка активна (`document.visibilityState`)
- Оптимистичная отправка (пузырь мгновенно, подтверждение со следующего опроса)
- При открытии — входящие непрочитанные помечаются прочитанными

### Компоненты
- `src/components/lk/ChatList.tsx`, `src/components/lk/ChatThread.tsx` (client)
- Страницы: `/lk/messages/page.tsx`, `/lk/messages/[applicationId]/page.tsx`
- Ключи словаря ru+os

## 3. Разделы ЛК (живые данные)

### `/lk/applications`
- Реальные заявки (user = я). Строка: бейдж типа · объект (ссылка) · дата · статус («Новая» золото / «В работе у агента» синий / «Завершена» зелёный / «Отменена» серый) · имя агента
- Клик → чат заявки
- Пустое состояние + CTA

### `/lk/favorites`
- Реальные user.favorites, сетка `ObjectCard`
- Пустое состояние + CTA

### `/lk/profile`
- Реальные данные (имя, телефон — редактируемые; email — просмотр), аватар-инициалы
- Сохранение через PATCH, кнопка «Сохранено ✓» на 2 сек

### `/lk` (dashboard)
- Счётчики на карточках разделов (избранное N, заявки N, новые сообщения N)

## 4. User-friendly моменты

- Бейдж непрочитанных на ссылке «Личный кабинет» в шапке (polling 30 сек)
- В шапке чата — фото/имя агента + кнопка «Позвонить»
- Скелетоны загрузки, «Отправка…» на кнопках, подтверждения действий
- После заявки с сайта — подталкивание в ЛК

## YAGNI (не делаем в этой итерации)

- Уведомления на почту/Telegram
- Вложения в чате (фото/документы)
- «Печатает…», онлайн-статус, голосовые
- Календарь показов, история сделки (взрослая CRM-фаза)
- Отмена заявки пользователем из ЛК
- Модерация чата
