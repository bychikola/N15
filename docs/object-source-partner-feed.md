# Подключение первого реального источника объектов (партнёрский JSON-фид)

Документ описывает, как подключить **один** внешний источник — партнёрский
JSON-фид по договору — через уже работающий модуль «Источники объектов»
(`src/lib/object-sources.ts`, `src/lib/object-source-service.ts`). Массовой
загрузки и автоматической публикации нет: забор только наполняет очередь CRM,
и по каждому объекту решение принимает сотрудник.

## 1. Правовое основание (обязательно)

Партнёрский канал имеет статус `needsAgreement`: **без договора с правообладателем
данных подключать его нельзя**. Перед подключением нужно:

- действующее соглашение с партнёром о приёме и публикации его объектов;
- адрес JSON-фида и токен доступа, выданные партнёром по договору.

Автосбор чужих объявлений (Авито, ЦИАН, Домклик, Яндекс Недвижимость) запрещён
правилами площадок и остаётся в реестре как недоступный канал. NMarket, XML и
другие площадки в этом этапе не подключаются.

## 2. Порядок подключения

1. Раздел CRM «Источники объектов» (`/crm/sources`), только администратор.
2. В настройках источника «Партнёрские агентства» задать **Адрес выгрузки**
   (`feedUrl`, http/https) и, если фид закрыт, **Токен доступа** (`token`) —
   они уходят заголовком `Authorization: Bearer`.
3. Включить источник и нажать «Запустить забор».

Забор ограничен потолком первого подключения — **не более 5 объектов за
прогон** (`importLimit` у источника `partner`). Повторный забор тех же записей
не задваивает очередь: кандидат ищется по паре «источник + `externalId`» и
обновляется.

## 3. Формат фида

Корень — массив объектов либо объект с массивом в одном из полей
`items`, `objects`, `data`, `results`, `listings`.

Поля одной записи (синонимы через `|`):

| Поле каталога | Ключи в фиде |
|---|---|
| Идентификатор (`externalId`) | `id`, `externalId`, `objectId` |
| Название | `title`, `name` |
| Регион / район | `region`, `district`, `areaName` |
| Адрес | `address` (строка или объект с `city`, `district`, `locality`, `street`, `house`) |
| Тип объекта | `category`, `objectType`, `propertyType`, `kind`, `type` |
| Вид сделки | `dealType`, `deal`, `operation` |
| Стоимость | `price`, `cost` |
| Площадь, м² | `area`, `square` |
| Комнат | `rooms`, `roomCount` |
| Описание | `description`, `text` |
| Фото | `photos`, `images` (ссылки или объекты с `url`) |
| Ссылка у источника | `url`, `link`, `sourceUrl` |
| Комиссия | `commission`, `fee` |
| Дата актуальности | `actualAt`, `updatedAt`, `updated` |

Пример одной записи:

```json
{
  "id": "A-1024",
  "title": "Двухкомнатная квартира, ул. Кирова",
  "region": "Иристонский",
  "address": { "city": "Владикавказ", "street": "Кирова", "house": "12" },
  "category": "Квартира",
  "dealType": "Продажа",
  "price": 4500000,
  "area": 54.5,
  "rooms": 2,
  "description": "Светлая квартира с ремонтом",
  "photos": ["https://partner.example/photos/1.jpg"],
  "url": "https://partner.example/objects/A-1024",
  "commission": "3 %",
  "actualAt": "2026-10-01T09:00:00.000Z"
}
```

## 4. Что происходит с данными

- Все объекты попадают в очередь со статусом **«Ждёт решения»**; автоматической
  публикации на сайт нет.
- Сохраняются: `externalId`, дата актуальности, регион, тип объекта, площадь,
  комнаты, стоимость, описание, фотографии.
- **Полный адрес** виден только внутри CRM: при переносе в каталог публично
  уходят город, район и улица без номера дома и квартиры.
- **Исходная ссылка и источник** доступны только администратору (полевой
  доступ в `SourceObjects.ts`).
- Персональные данные собственника (если партнёр их пришлёт) в очередь не
  переносятся.
- Одобренный кандидат переносится в каталог отдельным действием и заводится
  **черновиком** с ответственным агентом.
